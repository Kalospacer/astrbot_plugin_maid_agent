代理女仆 · 使用文档

主模型（大小姐）专注陪用户聊天，管家（子代理）在幕后调用工具执行任务。需要做事时通过 call_maid 派给管家，管家执行完回报给大小姐转告用户。

工具 API（模型调用）

工具call_maid

调度管家执行任务。默认前台同步等待，短任务当场返回；超时自动转后台并返回句柄。

参数类型必填说明
request_textstring必填任务要求（自包含背景/约束/目标）
agent_namestring可选目标管家名称，留空用默认
resume_agent_idstring可选恢复已有 agent；running 时等价 steer
run_in_backgroundbool可选true 立即转后台，默认前台等待
tasksarray可选批量任务，最多 5 项，仅新建 agent
工具maid_task

查询与控制后台任务，对齐 TaskOutput 语义。

参数类型必填说明
actionstring必填status / result / stop / steer
task_idstring按动作status/result/stop 时填
agent_idstring按动作steer 必填；result 可选校验
messagestringsteer 必填补充的要求文本
blockbool可选result 是否阻塞，默认 true
timeout_msint可选result 超时毫秒，默认 30000

用户命令

命令/maid status

查看当前后台管家任务状态；批量任务展示子任务明细。

命令/maid stop

请求停止当前后台管家任务；批量任务停止整批。

执行流程

  1. 大小姐判断需要做事时调用 call_maid。
  2. 短任务当场返回；超过前台阈值后转后台。
  3. 后台任务结束后唤醒大小姐整理结果转告用户。
  4. 期间可用 maid_task 查询或控制。

Agent 与 Run 模型

  • 新 dispatch 创建新 agent；显式 resume_agent_id 才恢复身份。
  • 每 agent 同时最多一个活跃 run；每会话最多 5 个、全局 20 个。
