代理女仆

一个 AstrBot 双代理插件。主模型（大小姐）专注陪用户聊天，管家（子代理）在幕后调用工具执行任务，让角色扮演既沉浸又能真正做事。

传统角色扮演 Agent 会把大量函数调用的系统提示词注入主模型，导致模型说话像刻板的 AI 助手。本插件把「聊天」与「做事」拆成两个角色：大小姐只保留纯净对话，需要做事时通过 call_maid 派给管家；管家接管全部工具能力，执行完再回报给大小姐转告用户。

运行前提

  • AstrBot >= 4.20.0。
  • 已在 AstrBot 启用 SubAgent（子代理编排） 功能，并至少配置一个可用 SubAgent。
  • 插件配置中的 default_agent_name 填成你那个 SubAgent 的名称。

快速开始

  1. 在 AstrBot 配置一个 SubAgent（可参考「SubAgent 配置」一节）。
  2. 启用本插件，在插件配置页填好默认管家名称。
  3. 正常聊天。大小姐需要做事时会自动调用 call_maid，管家在后台执行并回报。

工具 API

以下两个工具由插件注册给大模型，通过 function calling 调用，用户通常无需手动触发。

工具 call_maid

调度管家执行任务。默认前台同步等待（最多 foreground_timeout_seconds 秒），短任务当场返回结果；超时自动转后台并返回任务句柄。

名称类型必填描述
request_textstring必填交给管家的任务要求（自包含背景/约束/目标）。
agent_namestring可选目标管家名称，留空用默认管家。仅新建 agent 生效。
resume_agent_idstring可选恢复已有 agent；running 时等价 steer，终态时新建 task 后台执行。
run_in_backgroundbool可选true 立即转后台返回句柄；默认 false 前台等待。
tasksarray可选批量任务，每项 {request_text, agent_name?, run_in_background?}，最多 5 项。仅新建 agent。
工具 maid_task

查询与控制后台任务，对齐 Claude TaskOutput 语义。

名称类型必填描述
actionstring必填status 查状态 / result 等终态 / stop 停止 / steer 补充要求。
task_idstring按动作status/result/stop 时填写。
agent_idstring按动作steer 必填；result 可选用于归属校验。
messagestringsteer 必填steer 时补充的要求文本。
blockbool可选result 是否阻塞等待，默认 true。
timeout_msint可选result 阻塞超时毫秒，默认 30000，最大 600000。

用户命令

在聊天里直接输入，管理后台管家任务。

命令 /maid status

查看当前后台管家任务状态；若为批量任务，会展示各子任务明细。

命令 /maid stop

请求停止当前后台管家任务；若为批量任务，会停止整批。

执行流程

  1. 用户发消息，大小姐判断需要做事时调用 call_maid。
  2. 短任务在当前 tool turn 内直接返回结果；超过前台阈值后同一执行器原地转后台。
  3. 后台任务结束后写入 notification outbox，并唤醒大小姐整理结果转告用户。
  4. 期间可用 maid_task(status/result/stop/steer) 按 task/agent ID 查询或控制。

Agent 与 Run 模型

  • 每次新 dispatch 创建新 agent；只有显式 resume_agent_id 才恢复稳定身份。
  • 每个 agent 同时最多一个活跃 run；每个会话可并发多个不同 agent。
  • 每个会话最多 5 个活跃 run，全局最多 20，超限立即拒绝。
数据存储：data/plugin_data/astrbot_plugin_maid_agent/agents/<agent_id>/，含 agent.json、transcript.jsonl、runs/<task_id>.json、outputs/<task_id>.txt。元数据按 retention_days 清理（不删 memory）。

配置参考

配置全部在 AstrBot 插件配置页管理。

字段 插件配置
配置项默认说明
default_agent_namemuiceagent默认被调度的 SubAgent 名称。
allowed_agent_names[muiceagent]call_maid 可显式指定的 Agent 白名单。
hide_native_toolstrue隐藏主模型可见的原生工具，只保留 call_maid 与 maid_task。
hide_transfer_toolstruehide_native_tools=false 时额外隐藏全部 transfer_to_*。
include_raw_user_inputtrue把真实用户原话一并透传给管家。
foreground_timeout_seconds50前台等待阈值（秒），超时转后台。
memory_agent_names[]启用持久记忆与原生 Read/Write/Edit 的 agent 名称列表。
max_active_per_umo5每会话活跃 run 上限。
max_active_global20全局活跃 run 上限。
retention_days30元数据/run/transcript/output 保留天数（不删 memory）。
dispatch_prompt_template内置发送给管家的中继调度系统提示词模板。

调度模板支持占位符：{user_input_block}（用户原话块）、{maid_request_block}（自包含任务需求块）。

SubAgent 配置示例

在 AstrBot 全局配置或管理面板中配置一个 SubAgent。name 与插件配置一致即可，插件对名称做大小写适配，匹配不到时回退到第一个可用 SubAgent。

右栏「配置」标签页提供可复制的最小化 yaml 示例。

调用示例
工具与命令的使用方式
查看后台任务状态
/maid status
停止后台任务
/maid stop
call_maid 发起任务
{
  "name": "call_maid",
  "arguments": {
    "request_text": "帮我查一下今天深圳的天气并总结",
    "agent_name": "muiceagent"
  }
}
call_maid 批量任务
{
  "name": "call_maid",
  "arguments": {
    "tasks": [
      {"request_text": "整理下载目录"},
      {"request_text": "汇总本周日程", "run_in_background": true}
    ]
  }
}
maid_task 读取结果
{
  "name": "maid_task",
  "arguments": {
    "action": "result",
    "task_id": "task-xxxx",
    "block": true,
    "timeout_ms": 30000
  }
}
插件配置 config
default_agent_name: "muiceagent"
allowed_agent_names: ["muiceagent"]
hide_native_tools: true
hide_transfer_tools: true
include_raw_user_input: true
foreground_timeout_seconds: 50
memory_agent_names: []
max_active_per_umo: 5
max_active_global: 20
retention_days: 30
SubAgent 配置示例
subagent_orchestrator:
  agents:
    - name: muiceagent
      enabled: true
      system_prompt: |
        你是运行在 AstrBot 中的 MuiceAgent，
        作为子代理接收主代理指令并实际执行。
        零上下文启动，严格遵循 task 描述，
        主动决策，结果导向。
